# قانونِ سختِ ممیزیِ Neura (Audit Rulebook)

این سند «دانشِ ممیزی» است. هر باگی که از قلم افتاد، به‌صورتِ یک **قانون** اینجا اضافه می‌شود تا **تکرار نشود**.
قبل از اینکه هر واحد «تمام» اعلام شود، باید همهٔ قوانینِ مربوطه رعایت شده باشد. ادعای «درست شد» بدونِ
**شواهد** (اسکرین‌شاتِ رِندرِ واقعی + تستِ بک‌اندِ واقعی) ممنوع است.

## روشِ کار (غیرقابلِ‌مذاکره)
1. **واحدهای کوچک، تا ته.** یک تب/بخش در هر نوبت؛ هر دکمه، تب، منو، مودال و **جریانِ تودرتو** از اول تا آخر.
2. **با چشمِ واقعی.** هر حالت را رِندر کن، اسکرین‌شات بگیر، و **خودت نگاه کن** — نه فقط چک‌کردنِ وجودِ DOM.
3. **بک‌اندِ واقعی + دادهٔ واقعی.** روی Postgres واقعی و سرورِ واقعی؛ نه stubِ فیک.
4. **سه‌گانهٔ راستی‌آزمایی:** کد + رِندرِ واقعی + رفتارِ بک‌اند. اگر هر سه هم‌خوان نبودند، هنوز تمام نشده.
5. **بعد از هر تغییر**، صفحه‌های متأثر را دوباره رِندر و بصری چک کن (رگرسیون‌گیری).

## قوانین (از باگ‌های واقعیِ این پروژه)
- **R1 — قابلِ‌کلیک ≠ کارکردن.** هر المانِ قابلِ‌کلیک باید **واقعاً باز/اجرا شود** و نتیجه‌اش **دیده شود**. «در DOM هست» کافی نیست.
- **R2 — دیده‌شدن (z-index/پرتال).** منو/مودالی که باز می‌شود باید **روی محتوا** بنشیند، نه پشتش. عناصرِ `absolute` که ممکن است زیرِ کارت‌ها بروند → **پرتال به body + fixed**. [باگ: کشوییِ دستیار پشتِ کارت‌ها پنهان بود]
- **R3 — همهٔ نقش‌ها.** منطقِ نقش‌محور (`role==='user'` و …) را با **admin و user هر دو** تست کن. [باگ: نمونهٔ دستیار فقط برای user بسط می‌شد؛ برای admin نه]
- **R4 — مسیرِ به‌دست‌آوردن باید وجود داشته باشد.** اگر UI یک قابلیت را نشان می‌دهد (سوییچرِ چند-نمونه)، باید راهِ واقعیِ ساختن/خرید هم باشد. [باگ: سوییچرِ چند-دستیار بود ولی خریدش نبود]
- **R5 — Hooks پیش از هر return.** هیچ `useState/useEffect` بعد از `if(...) return null` نگذار. [باگ: کرشِ سفیدِ چت، React #310]
- **R6 — رِندرِ امنِ داده.** آرایه/آبجکت را مستقیم به‌عنوان فرزندِ React رِندر نکن. [باگ: کرشِ سفارشاتِ داین، React #31]
- **R7 — بدونِ fallbackِ فیک.** الگوی `real > 0 ? real : [hardcoded]` ممنوع؛ خالی، خالی نشان داده شود. [باگ: CRM 45/28/18/12 ویترینی]
- **R8 — ماندگاری واقعی.** فرم/خرید بعد از ثبت باید با **خواندنِ دوباره از DB** تأیید شود، نه toastِ خوش‌بینانه.
- **R9 — تبِ فعال، دکمهٔ مرده نیست.** کلیکِ تبِ ازقبل‌انتخاب‌شده = no-opِ درست؛ آن را «مرده» گزارش نکن (تلنگرِ حالت بزن).
- **R10 — ماژولی/مشترک.** رفتارِ مشترک (خرید/چت/…) در **یک ماژول/کامپوننت** باشد تا تغییر یک‌جا همه‌جا اعمال شود.
- **R11 — سوپرادمین را واقعاً چک کن.** پنلِ سوپرادمین اپِ جداست؛ ادعای «چک کردم» بدونِ رِندرِ واقعیِ صفحه‌هایش ممنوع.
- **R12 — صداقت.** اگر چیزی را تست نکرده‌ای، بگو «تست نکردم». هیچ‌وقت «درست شد» بدونِ شواهد نگو.

## چک‌لیستِ هر واحد (قبل از «تمام»)
- [ ] هر تبِ داخلِ این بخش باز شد و محتوا/کرش/سفیدی چک شد؟
- [ ] هر دکمه/منو/مودال باز شد و نتیجه‌اش **دیده** شد (اسکرین‌شات)؟
- [ ] جریان‌های تودرتو تا **آخر** رفته شد (نه فقط سطحِ اول)؟
- [ ] با هر دو نقشِ user و admin (در صورتِ ربط) تست شد؟
- [ ] داده‌ها از بک‌اندِ واقعی‌اند (نه فیک/هاردکد)؟ ماندگاری با DB تأیید شد؟
- [ ] رگرسیون‌گیری بعد از تغییر انجام شد؟
- [ ] هر باگِ نو به‌عنوانِ قانونِ جدید به همین فایل اضافه شد؟

> هر بار که باگی از قلم افتاد، **اول** قانونش را اینجا اضافه کن، **بعد** رفعش کن.
